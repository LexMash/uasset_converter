# Конвертер ассетов Unreal → Unity

Переносит арт из проекта Unreal Engine в Unity: текстуры, меши, анимации и
материалы. Мастер-материалы Unreal транспилируются в настоящие HLSL-шейдеры, а
не приближаются вручную подобранными значениями. Целевой пайплайн — **URP**.

Запускается двумя способами: своим окном или прямо из Unity, меню
**Tools → Uasset Converter**. Интерфейс переключается между языками, локали
добавляются одним файлом — см. [docs/LOCALIZATION.md](docs/LOCALIZATION.md).

## Что нужно

- **Unreal Engine 5.8** — конвертер использует родные экспортёры движка, поэтому
  геометрия и текстуры получаются оригинального качества, а не восстановленные
  парсером `.uasset`.
- **Python 3.13** — `tkinter` для интерфейса входит в стандартную поставку.
  Дополнительно ставятся `pillow` и `numpy` (см. шаг 0).
- **Unity 6000.x или 2022.3 LTS** с **URP**. HDRP не поддерживается: его проходы
  Lit — внутреннее дело пайплайна, и рукописным HLSL-шейдером их не воспроизвести.

Проект Unreal должен быть **исходным проектом**, а не запакованной игрой:
конвертер открывает его редактором.

## Порядок работы

Процесс из двух частей: сначала конвертер вытаскивает всё из Unreal в папку
`output`, потом импортёр внутри Unity затягивает `output` в проект. Папка
`output` — единственное, что их связывает.

```
Unreal ──► convert.py ──► output/ ──► импортёр в Unity ──► Assets/
           (3 шага)                    (одна кнопка)
```

Запускать конвертер можно откуда удобнее — своим окном или прямо из Unity.
Делают они одно и то же и правят один и тот же `config.json`.

### Шаг 0. Один раз

```bash
python -m pip install -r requirements.txt
```

В целевом Unity-проекте должен стоять пакет **URP** и, главное, быть **назначен
URP-ассет** в Project Settings → Graphics и в Quality. Пакет сам по себе
пайплайн не включает: без назначенного ассета материалы создадутся, но
отрисуются неправильно.

### Шаг 1. Конвертация (сторона Unreal)

```bash
python convert.py
```

Откроется окно. Порядок действий сверху вниз:

1. **Пути** — укажи `.uproject`. Папка движка подставится сама из реестра.
2. **Объём** — начни с «Тестовая выборка»: прогон на всём `Content` долгий, а
   ошибку в маппинге материалов дешевле поймать на десятке ассетов. Для режима
   «Выбранные папки» отметь галочками нужное в дереве ниже.
3. **Сканировать** — быстрый подсчёт по файлам, без запуска Unreal. Нужен
   просто чтобы понимать масштаб.
4. **Всё целиком** — запускает три шага подряд.

Три шага, если хочется по одному (кнопки идут в этом же порядке слева направо):

| Кнопка | Что делает | Чем питается |
|---|---|---|
| **Экспорт из Unreal** | запускает headless-редактор, выгружает текстуры/меши/анимации, снимает графы материалов | проектом Unreal |
| **Сгенерировать шейдеры** | транспилирует мастер-материалы в `.shader` | `output/manifest.json` |
| **Постобработка** | перепаковывает маски, собирает манифест для Unity | `manifest.json` + `shaders.json` |

Порядок обязателен — каждый следующий шаг читает результат предыдущего.
Отдельные кнопки нужны, когда правишь `config.json`: маппинг материалов
перепрогоняется «Постобработкой» за секунды, без повторного запуска Unreal.

**Первый запуск занимает 10–20 минут** — движок прогревает DDC и компилирует
шейдеры. Дальше минуты. Прогресс и лог видно прямо в окне, «Отмена» убивает
процесс редактора.

То же самое из консоли:

```bash
python convert.py --cli --step all --scope test --lang en
```

`--step`: `export`, `shaders`, `postprocess`, `all`.
`--scope`: `test` (выборка из `config.json`), `selected` (папки из
`scope.include_paths`), `all` (весь `Content`).
`--lang`: код языка или `auto`.

#### То же самое из Unity

Меню **Tools → Uasset Converter**. Окно повторяет всё то же самое: пути,
галочки, выбор папок, те же кнопки шагов — и одну лишнюю,
**«Конвертировать и импортировать»**, которая по завершении сразу затягивает
результат в проект, без второго окна и второй кнопки.

Шаг экспорта идёт через Python, встроенный в сам Unreal, — ставить его не надо.
А вот генерация шейдеров и постобработка — обычные скрипты, и им нужен
системный Python 3 с `pillow` и `numpy`. Окно ищет его само (`PATH`, лаунчер
`py -3`, типовые места установки) и, если чего-то не хватает, показывает точную
команду установки, а не падает посреди работы.

Лог и прогресс идут в окно построчно, редактор при этом не подвисает: процесс
читается в фоне, а разбирается в `EditorApplication.update`. Кнопка «Отмена»
убивает процесс.

### Шаг 2. Установка пакета в Unity

Один раз на проект. В окне конвертера — кнопка **«Пакет в Unity…»**, выбрать
папку проекта Unity. Конвертер пропишет себя в `Packages/manifest.json`:

```json
"com.uasset.converter": "file:C:/.../uasset_converter/unity/com.uasset.converter"
```

Вручную это то же самое: Package Manager → **Add package from disk** →
`unity/com.uasset.converter/package.json`.

Пакет, а не копирование файлов в `Assets`: он не мусорит в проекте, не
попадает в чужие коммиты и обновляется вместе с конвертером.

### Шаг 3. Импорт (сторона Unity)

Меню **Tools → Uasset Converter → Import**. В окне:

| Поле | Что ставить |
|---|---|
| **Папка output** | та самая `output` конвертера — кнопка «Обзор…» |
| **Куда в проекте** | `Assets/UassetConverted` по умолчанию |
| **Аватар скелеток** | `Generic` работает всегда; `Humanoid` — если нужен ретаргет |
| **Перезаписывать файлы** | оставь включённым для повторных прогонов |

Кнопка **«Импортировать»**. Копировать файлы руками не нужно — импортёр сам
переносит их из `output` в `Assets`, сохраняя структуру папок Unreal.

Дальше он идёт строго по порядку, и порядок здесь не косметика:

1. копирует файлы и шейдеры — материалам нужно, на что садиться;
2. настраивает текстуры — материалам нужны корректные нормали и sRGB;
3. создаёт материалы;
4. настраивает модели и привязывает к ним материалы;
5. импортирует скелетные меши — на этом шаге рождаются аватары;
6. импортирует клипы — им нужны аватары из шага 5.

Результат: меши в `Assets/UassetConverted/Meshes/…` уже с материалами на
слотах, ничего доводить в инспекторе не надо.

### Шаг 4. Что посмотреть после

Открой **`output/unsupported.md`** — он пересобирается каждый прогон и
перечисляет всё, что не перенеслось или перенеслось приблизительно.

Отдельно проверь глазами две вещи, которые конвертер знать не может:
**направление рельефа** от карт нормалей (флаг `textures.flip_normal_green`) и
**зацикливание анимаций** (оно угадано по имени клипа).

## Язык интерфейса

Переключается в шапке любого из двух окон и запоминается в `config.json`
(`language`, значение `auto` — определить по системе). Язык влияет не только на
интерфейс: на нём же собирается отчёт `output/unsupported.md` и комментарии в
сгенерированных шейдерах.

Причины пропуска и пометки TODO хранятся в манифесте **ключами**, а не готовым
текстом. Поэтому отчёт всегда на том языке, который выбран сейчас, а не на том,
на котором когда-то запускали экспорт.

Добавить свой язык — это положить один JSON-файл, кода трогать не нужно:
[docs/LOCALIZATION.md](docs/LOCALIZATION.md).

## Как это устроено

Слои, каждый можно запускать и чинить отдельно.

| Файл | Что делает |
|---|---|
| `convert.py` | Оркестратор и CLI. Он же обслуживает окно в Unity: `--config-dump`, `--config-set`, `--scan-folders`, `--porcelain`. |
| `gui.py` | Своё окно. Ничего не считает — редактирует конфиг и запускает шаги. |
| `i18n.py` | Локализация. Файлы локалей общие с Unity-пакетом. |
| `ue_export.py` | Выполняется **внутри** Unreal. Экспортирует файлы, снимает графы материалов и функций. |
| `graph_ir.py` | Граф Unreal → нейтральное промежуточное представление. |
| `backend_hlsl.py` | IR → `.shader`. |
| `shader_gen.py` | Оркестровка: манифест → шейдеры. |
| `postprocess.py` | Разрешение параметров, перепаковка каналов, манифест для Unity. |
| `unity/com.uasset.converter/` | UPM-пакет: окно конвертера, импортёр. |

Почему обход графа и генерация текста разведены: обход в `graph_ir.py` даёт
нейтральный список операций с известными размерностями, а `backend_hlsl.py`
рендерит из него текст `.shader`. Новая нода добавляется один раз, в
`graph_ir.py`, и покрытие расширяется дёшево.

### Почему запускается полный редактор, а не commandlet

Изначально экспорт шёл через `-run=pythonscript`. На скелетных мешах это
роняет движок:

```
Assertion failed: MeshObject [SkinnedMeshComponent.cpp:4987]
```

Экспортёру скелетки нужен живой рендер-контекст, а commandlet его не поднимает.
Поэтому используется `-ExecutePythonScript` с полным редактором и
`-RenderOffScreen`: RHI работает, окна на экране нет.

Первый запуск занимает 10–20 минут — движок прогревает DDC и компилирует
шейдеры. Дальше это разово и быстро.

### Транспиляция материалов

Мастер-материалы Unreal — это графы нод. Переносится:

- **математика и утилиты** — Multiply, Add, Subtract, Divide, Lerp, Clamp,
  Power, Min, Max, Fmod, Step, SmoothStep, If, Dot, Cross, Distance, Length,
  Normalize, Abs, Saturate, Frac, Floor, Ceil, Round, Sign, Sqrt, Sine, Cosine,
  Tangent, Arcsine, Arccosine, Arctangent, Arctangent2, DDX, DDY, экспоненты и
  логарифмы, ComponentMask, AppendVector, OneMinus, Desaturation,
  ConstantBiasScale, DeriveNormalZ;
- **координаты** — TextureCoordinate (до четырёх наборов UV), Panner, Rotator,
  CustomRotator, BumpOffset;
- **входы поверхности** — VertexColor, нормаль, позиция в мире, позиция и
  масштаб объекта, вектор камеры, экранная позиция, Time, TwoSidedSign,
  Fresnel, SphereMask;
- **параметры** — Scalar, Vector, Texture, StaticSwitch (становится
  `shader_feature`, а не рантайм-ветвлением);
- **любая функция материала** — её граф выгружается из Unreal и разворачивается
  инлайном. Захардкоженного списка функций нет; `CheapContrast` и
  `BlendAngleCorrectedNormals` оставлены ручными реализациями только потому,
  что они короче и дешевле развёрнутого графа;
- **нода Custom** — HLSL из неё переносится как есть, а не выбрасывается;
- **провода** — Reroute и именованные reroute проходят насквозь.

Незнакомая нода не выдумывается: она пробрасывает первый вход, оставляет
`// TODO` в коде рядом с этим местом и строку в `output/unsupported.md`.

Граф читается через `unreal.MaterialEditingLibrary` — `get_material_expressions`,
`get_inputs_for_material_expression`, `get_material_property_input_node`.
Через `get_editor_property` он недоступен: свойство `Expressions` защищено.

Что это даёт: параметры `MaterialInstanceConstant` ложатся на свой шейдер
**по именам, без эвристик**, и сохраняются вещи, ради которых мастера и
писались — detail-нормали, контраст на roughness, per-instance тайлинг.

Пример. `MI_Floor_A` в Unreal и в Unity после конвертации — одни и те же
параметры с теми же именами:

```
_Diffuse, _Normal, _Roughness            (текстуры)
"Base Rough Min" = 0.15                  (было 0.3 в мастере)
"Base Rough Max" = 0.6
"Metal" = 1.0,  "Color" = (0.36, 0.36, 0.36)
```

Материалы, чей мастер не транспилировался, собираются на дефолтном `URP/Lit`
по таблице соответствия имён из `config.json`.

### Формат вывода шейдеров

Транспилятор пишет самодостаточный HLSL — `output/Shaders/*.shader` под
URP/Lit. Шаблон не подключает `LitInput.hlsl` из пакета URP, поэтому файл
переживает обновления пакета.

### Перепаковка каналов

Unreal хранит **roughness**, Unity ждёт **smoothness** — это инверсия, а не
переименование. URP/Lit к тому же требует `_MetallicGlossMap`, где RGB —
металличность, а альфа — smoothness. Такой карты в Unreal нет, её собирает
`postprocess.py` из раздельных Rough/Metal, из упакованных MRA/ORM или из
скалярных значений.

Раскладка упакованных карт описана в `PACKED_LAYOUTS`: `MRA` — Metallic /
Roughness / AO, `ORM` — Occlusion / Roughness / Metallic и так далее.

Собственным транспилированным шейдерам эта перепаковка не нужна: они читают
roughness напрямую, как в Unreal.

### Нормали

Unreal хранит карты нормалей в конвенции DirectX (зелёный канал вниз), Unity
ждёт OpenGL (вверх), поэтому зелёный канал инвертируется. Отключается флагом
`textures.flip_normal_green` в конфиге — **проверь на первом же освещённом
объекте**, что рельеф идёт в нужную сторону.

Карты нормалей опознаются по типу сжатия `TC_NORMALMAP` из самого Unreal, а не
по имени файла: имена вроде `T_Manny_01_BN` ни под какой шаблон не попадают.

### Почему материалы у модели импортируются, а не выключены

Логика просит `materialImportMode = ImportViaMaterialDescription` и
`materialLocation = InPrefab` — в инспекторе это «Import via MaterialDescription»
и «Use Embedded Materials».

Выглядит нелогично: свои материалы уже собраны из данных Unreal, зачем импортёру
трогать материалы FBX. Но при `materialImportMode = None` Unity вообще не
смотрит на имена материалов в файле, и **таблица ремапов перестаёт работать** —
записи в `.meta` есть, а меш приезжает с дефолтным серым материалом.

Ошибку легко не заметить: материалы созданы, шейдеры компилируются, `AddRemap`
отработал, все проверки зелёные. Поэтому в `UassetBatchVerify` есть отдельная
проверка `CheckMeshBindings` — она поднимает импортированную модель и смотрит,
что на её рендерерах стоят именно наши материалы.

## Настройка

Всё в `config.json`. Его нет в репозитории — он содержит абсолютные пути
конкретной машины; при первом запуске создаётся копированием
`config.default.json`. Ключи, появившиеся в новых версиях, добираются в
существующий конфиг автоматически, поэтому обновление не ломает настройки.

- `scope.test_subset` — список ассетов для тестового прогона. Зависимости
  подтягиваются автоматически: материал приедет со своими текстурами.
  **Анимации нужно добавлять явно** — зависимости идут вниз, и клип ссылается
  на скелет, а не наоборот.
- `language` — код языка интерфейса или `auto`.
- `paths.python` — интерпретатор для окна в Unity. Пусто — искать самому.
- `shader_gen.roots` — какие пути транспилировать в шейдеры.
- `shader_gen.skip` — мастера, которые сознательно не транспилируются
  (декали, партиклы, UI), с причиной в `skip_reason`.
- `material_mapping` — таблица соответствия имён для fallback-пути.
- `animations.loop_patterns` — эвристика зацикливания клипов.

## Перенос на другой проект Unreal

Сам код проекту не принадлежит: обход идёт по Asset Registry и диспетчеризуется
по классу ассета, никаких «зашитых» имён в логике нет. Привязка к конкретному
проекту живёт только в `config.json`, и менять надо четыре вещи:

| Ключ | Что поставить |
|---|---|
| `paths.ue_project` | путь к новому `.uproject` (в GUI — «Обзор…») |
| `paths.output_dir` | куда складывать результат |
| `scope.include_paths` | папки нового проекта (в GUI — дерево с галочками) |
| `shader_gen.roots` | какие пути транспилировать в шейдеры |

`scope.test_subset` и `shader_gen.skip` тоже указывают на ассеты ModSci — для
другого проекта их надо переписать или просто не пользоваться режимом «тестовая
выборка». `material_mapping` менять не обязательно: правила там по именам
параметров, а не по проекту.

### Что будет с чужими мастер-материалами

Транспилятор понимает такой набор нод:

```
Add Subtract Multiply Divide LinearInterpolate Clamp Saturate Abs OneMinus Power
Desaturation AppendVector ComponentMask Constant Constant2/3/4Vector
ScalarParameter VectorParameter StaticSwitchParameter StaticBoolParameter
TextureSample TextureSampleParameter2D TextureObjectParameter
TextureCoordinate Panner MaterialFunctionCall
```

Из функций движка перенесены две: `CheapContrast_RGB` и
`BlendAngleCorrectedNormals`.

Ноду вне этого списка транспилятор **не выдумывает**. Он подставляет первый
подключённый вход, ставит рядом `// TODO` и пишет материал и номер ноды в
`output/unsupported.md`. Шейдер при этом скомпилируется, но результат будет
приблизительным — молчаливой подмены не будет, но и «оно само разберётся» тоже.

Чего в списке нет и что реально встречается в чужих паках: `Fresnel`,
`VertexColor`, `WorldPosition`, `Time`, `If`, `Min`/`Max`, `Sine`/`Cosine`,
`Dot`, `Normalize`, `CustomExpression`, а также любые `MaterialFunctionCall`
кроме двух известных. Каждая такая нода добавляется в `shader_gen.py` одним
методом `node_<Имя>` — расширять дёшево.

### Почему только URP

HDRP не поддерживается: состав и порядок его проходов Lit — внутреннее дело
пайплайна, и поддерживаемого способа написать такой шейдер вручную Unity не
даёт. Транспилятор пишет URP HLSL, поэтому:

- транспилированные шейдеры — `output/Shaders/*.shader` под URP/Lit;
- fallback-материалы — на дефолтном `Universal Render Pipeline/Lit`;
- карта масок — `_MetallicGlossMap` (RGB = metallic, A = smoothness),
  окклюзия — отдельной картой `_OcclusionMap`.

Сами `.shader` самодостаточны: кроме пакета URP они ни от чего не зависят и
переносятся в любой URP-проект простым копированием вместе с материалами.

## Что НЕ переносится

Читай `output/unsupported.md` после каждого прогона — он собирается заново и
перечисляет всё, что не перенеслось или перенеслось приблизительно.

Принципиально не переносятся:

- **Блюпринты и Anim Blueprint** — это логика, её надо писать заново.
- **Niagara** — прямого аналога системе частиц в Unity нет.
- **Уровни** — переносится арт, из которого они собраны, но не расстановка.
- **Декали** — в URP это отдельная механика (Decal Projector).
- **Physics Asset** — коллайдеры настраиваются в Unity.

Требуют проверки глазами:

- **Зацикливание анимаций** — Unreal этот признак не хранит, он угадан по имени.
- **Направление нормалей** — см. выше про `flip_normal_green`.
- **Humanoid-аватар** — по умолчанию `Generic`, он работает всегда. `Humanoid`
  включается в интерфейсе, но автомаппинг костей UE5 Unity может не собрать.
- **Параметр Specular** — в metallic-workflow Unity его нет, значение из Unreal
  отбрасывается.

## Проверка

### Тесты питоновской части

```bash
python -m pytest tests/
```

Что они ловят. `tests/golden/*.shader` — эталоны сгенерированных шейдеров:
их задача не в том, что они «правильные», а в том, что они **не меняются**.
Осознанное изменение фиксируется перегенерацией:

```bash
UAC_REGEN=1 python -m pytest tests/test_shader_golden.py
```

и в ревью диффом видно ровно то, что изменилось в шейдерах. Остальное:
`test_nodes.py` — каждая новая нода действительно переносится и не оставляет
TODO; `test_pipelines.py` — раскладка URP-карты масок собрана верно;
`test_pipeline_smoke.py` — шаги стыкуются между собой на обоих языках;
`test_locale_keys.py` — каждый ключ `Loc.T`, который использует C#-сторона,
существует, и каждому плейсхолдеру в нём передан аргумент.

Локали проверяются отдельно:

```bash
python tools/lint_locales.py
```

### Проверка в Unity

Две разные проверки, и одной первой недостаточно.

**1. Пакетный импорт** — копирование, настройки текстур, материалы, модели, клипы:

```bash
"C:\Program Files\Unity\Hub\Editor\6000.4.1f1\Editor\Unity.exe" -batchmode -quit -projectPath "<проект>" -executeMethod UassetImporter.UassetBatchVerify.Run -uassetOutput "<...>\output" -uassetLang ru -logFile verify.log -nographics
```

**2. Рендер-проверка** — включает URP, ставит сферы со всеми материалами и
рендерит кадр в PNG:

```bash
"C:\Program Files\Unity\Hub\Editor\6000.4.1f1\Editor\Unity.exe" -batchmode -quit -projectPath "<проект>" -executeMethod UassetImporter.Verify.UassetRenderCheck.Run -uassetShot shot.png -uassetLang ru -logFile render.log
```

Файлы для неё лежат в сэмпле пакета (`Samples~/RenderCheck`) и в импортёр не
входят: они жёстко завязаны на API создания URP-ассета пайплайна, которого
ядру импортёра знать незачем. Ставится через Package Manager → пакет →
Samples → Import.

Пояснительный текст обеих проверок локализован, а машинные маркеры — нет:
строка `RESULT: OK` / `RESULT: PROBLEMS FOUND`, префикс `[UASSET-VERIFY]` и код
возврата остаются одинаковыми на любом языке, чтобы по ним можно было грепать
лог в CI.

Язык задаётся аргументом `-uassetLang ru`. Без него берётся тот, что выбран в
окне конвертера; на чистой машине CI — системный, с откатом в английский.

### Почему одной первой проверки мало

HLSL в Unity компилируется **лениво** — не при импорте шейдера, а когда
впервые понадобился конкретный вариант. Поэтому сразу после импорта
`ShaderUtil.GetShaderMessages` возвращает пустой список даже у заведомо битого
шейдера, и первая проверка честно рапортует «ошибок нет».

Ровно так и вышло при разработке: пакетная проверка показала 0 ошибок по всем
пяти шейдерам, а на рендере половина сфер оказалась розовой. Причина нашлась
только в полном логе Unity — `float3(x)` из одного скаляра. Это правило GLSL;
в HLSL конструктор вектора требует ровно столько аргументов, сколько компонент,
и писать надо `float3(x, x, x)`.

В обоих логах ищи `[UASSET-VERIFY]`. Последняя строка — `РЕЗУЛЬТАТ: OK` или
`РЕЗУЛЬТАТ: ЕСТЬ ПРОБЛЕМЫ`; код возврата ненулевой, если что-то сломалось.
Если сфера розовая, а результат `OK` — ищи в логе Unity строки `Shader error in`.

## Логи

- `logs/ue_export.log` — полный вывод редактора Unreal.
- `output/manifest.json` — сырые данные из Unreal.
- `output/shaders.json` — какой мастер стал каким шейдером.
- `output/unity_manifest.json` — то, что читает C#-импортёр.
- `output/unsupported.md` — отчёт о непереносимом.
