# Как добавить перевод

Конвертер состоит из двух половин — питоновской и редакторной на C#, — но
локали у них общие. Один файл переводит и окно конвертера, и окно импорта в
Unity, и отчёт `unsupported.md`. Знать про две половины переводчику не нужно.

## Где лежат файлы

```
unity/com.uasset.converter/Editor/Locales/
    en.json     эталон, от него считаются все остальные
    ru.json
```

Внутри Unity можно ничего не трогать в пакете: файл с тем же именем, положенный
в `Assets/UassetLocales/`, перекрывает пакетный. Так удобно править перевод, не
конфликтуя с обновлением пакета.

## Как создать новый язык

```bash
python tools/lint_locales.py --new de
```

Появится `de.json` со всеми ключами и пустыми значениями. Дальше:

1. Заполни `name` — так язык будет подписан в выпадающем списке. Пиши название
   на самом языке: `Deutsch`, а не `German`.
2. Впиши себя в `authors`.
3. Переводи значения `v`, глядя на английский текст того же ключа в `en.json`.

Ключи (`k`) менять нельзя — по ним код находит строку.

## Формат

```json
{
  "code": "de",
  "name": "Deutsch",
  "fallback": "en",
  "authors": ["Имя переводчика"],
  "entries": [
    { "k": "gui.title", "v": "Unreal-zu-Unity-Asset-Konverter" }
  ]
}
```

`fallback` — язык, из которого берётся строка, если ключ ещё не переведён.
Почти всегда это `en`. Пустое значение равносильно отсутствию перевода: строка
подтянется из запасного языка, а не покажется пустой.

Формат намеренно плоский — массив пар вместо словаря. Так его читает и Python,
и `JsonUtility` в Unity, которому словари недоступны.

## Плейсхолдеры

Фрагменты в фигурных скобках — это подстановки. Их **набор** менять нельзя,
**порядок** — можно и нужно, если того требует язык:

```
"gui.progress.of": "{done} of {total} — {label}"      можно переставить
"gui.progress.of": "{label}: {done}/{total}"          тоже верно
"gui.progress.of": "{done} von {gesamt}"              ошибка: {gesamt} не существует
```

Потерянный или переименованный плейсхолдер — не косметика: сообщение падает с
ошибкой в момент показа, посреди долгого экспорта. Именно поэтому проверка
плейсхолдеров жёсткая.

Двойные скобки `{{` и `}}` — это экранированная фигурная скобка, оставь как есть.

## Проверка

```bash
python tools/lint_locales.py
```

Скрипт сверяет каждый файл с `en.json`: отсутствующие ключи, лишние ключи,
пустые значения, несовпадение плейсхолдеров. Ненулевой код возврата означает,
что что-то надо поправить. Прогони его перед тем, как присылать перевод.

Проверить только свой язык:

```bash
python tools/lint_locales.py --only de
```

## Как прислать

Pull request с одним файлом `<код>.json`. Ничего больше в PR быть не должно.

Код языка — по BCP 47: `de`, `fr`, `pt-BR`, `zh-Hans`. Если у языка есть
заметно разные варианты, лучше отдельные файлы, чем компромисс в одном.

## Правило для тех, кто меняет код

`en.json` и `ru.json` собираются из общей таблицы:

```bash
python tools/build_locales.py
```

Правится `tools/build_locales.py`, а не JSON-файлы напрямую — иначе английский
и русский разъедутся. Локали сообщества этот скрипт не трогает.

Новая строка в интерфейсе — это новый ключ в таблице сразу с обоими языками.
Локали сообщества догоняют позже; до тех пор недостающая строка показывается
по-английски, и это нормально — работать это не мешает.
